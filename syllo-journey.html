なぜ Why

Why I built this

Every long course has the same problem: you remember that something was explained well, somewhere, but not where. So you scrub back and forth through hours of video looking for four minutes you half-remember. I wanted an assistant that had actually watched the whole course — one I could just ask, and it would tell me exactly which video and which timestamp to go to, instead of making me search again.
I could have used an off-the-shelf tool. I didn't, because the point was never just to get an answer — it was to actually build the thing that gets the answer. Transcription, chunking, embeddings, retrieval, grounded prompting: I wanted to understand each of those pieces by wiring them together myself, not by reading about them.
The model was never the hard part. Chunking strategy and retrieval quality decide almost everything about whether an answer is useful — and most of the real work turned out to be unglamorous plumbing: cleaning transcripts, merging fragments into coherent chunks, keeping timestamps aligned through every stage. That's not what I expected going in.
02
いま Where it stands

v1.0, end to end

The whole pipeline runs today, start to finish. No frontend yet, and that's deliberate — I'd rather get the thinking right before I dress it up.

聴
Listen
Every video is transcribed and translated into timestamped text, no matter what language it was taught in.
憶
Remember
Cleaned, merged chunks are embedded into vectors — meaning gets stored, not just words.
答
Answer
A question is matched by meaning, and answered only from what's actually taught — with a timestamp attached.
03
これから What's next

The path ahead

Five things I'm working toward, in roughly the order I plan to tackle them. Tap one open.

01 Sharpen retrieval ▾
Better chunking than fixed groups of five, re-ranking retrieved chunks instead of trusting raw cosine similarity, and an actual evaluation set — so "is this a good answer" stops being a guess.
02 Bring in a real ML framework ▾
Right now embeddings and generation come from local servers I call by convention. I want that layer built on something like PyTorch or Hugging Face, so the model underneath is swappable without touching retrieval code.
03 Train on different data ▾
This currently assumes one course, one structure, one language. Generalizing it means any set of lecture videos should index cleanly, side by side, without rewriting the pipeline each time.
04 Fine-tune ▾
Teach a small model to answer the way a good teaching assistant actually does: grounded in the source, always citing a timestamp, and honest when a question falls outside what's been taught.
05 Build the frontend ▾
Deliberately last. A polished interface on top of a weak brain is worse than no interface at all — this comes once the answers underneath are actually worth showing off.

学び続ける Still learning
桜

This is version 1.0 — the first time every piece worked together, not the finished thing. I'm treating it as a running log of what I'm learning, not a product I'm done with. The plan is to keep building it in public increments: a little more accurate, a little more general, a little more honest about what it doesn't know — and to keep learning everything that takes, one version at a time.
